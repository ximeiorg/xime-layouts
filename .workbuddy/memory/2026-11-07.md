## GitHub Actions 支持按日期发 Release

- `.github/workflows/release.yml` 从「仅 release: published」扩成三触发：`schedule`（每天 00:05 北京时间）+ `workflow_dispatch`（可填 tag、可 force）+ `release: published`（沿用原行为，只传附件不改标题/说明）。
- cron 用 UTC `5 16 * * *`（= 次日 00:05 北京），日期用 `TZ=Asia/Shanghai date +%Y.%m.%d`，tag 形如 `v2026.11.07`。
- 跳过逻辑：当天已发过该 tag → 跳过；自上一个 release 以来没有 `*.yaml|*.yml` 变化 → 跳过（`::notice::`，不算失败）。`force` 可绕过。
- 关键坑（都已在脚本里处理）：`gh release list -q '.[0].tagName'` 在无 release 时输出字面量 `null` → 用 `// ""` + 再兜一次；上一个 release 的 tag 本地不存在时清空，否则当 `previous_tag` 传给 API 会 422；同一天重发靠 `overwrite_files: true` 覆盖附件。
- 校验：本地用 7 个场景跑过 meta 脚本（无 release / 有改动 / 当天已发 / force / 指定 tag / release 事件 / tag 不存在），行为符合预期；打包脚本在 /tmp 副本里跑通，10 个目录各出一个 zip。
- 注意 GitHub 会在仓库 60 天无提交后停用定时工作流（发 release 不算活跃）。

### 修正：去掉定时触发（用户要求）

- 移除了 `schedule` / cron，也不再需要 `force` 输入与「无变化跳过」逻辑；现在只有 `workflow_dispatch`（tag 留空 = 当天 `vYYYY.MM.DD`）和 `release: published` 两种触发。
- 手动运行一律打包发布；同一 tag 重复跑靠 `overwrite_files: true` 覆盖附件；`previous_tag` 仍取上一个 release（相等时置空，避免自己比自己）。
- 脚本里把 `[ cond ] && action` 改成 `if` 块，避免 `set -e` 下 AND-list 返回非零的边界问题。

### 修正：日期 tag 去掉 v 前缀（用户要求）

- `tag="v$(TZ=Asia/Shanghai date +%Y.%m.%d)"` → `tag="$(TZ=Asia/Shanghai date +%Y.%m.%d)"`，即 `2026.11.07` 这种形式。
- 同步改了 workflow 头部注释、`tag` 输入的 description、README「发布」表格里的示例。
- `release: published` 与手动填写的 tag 原样使用，不做前缀增删。
- 注意：本仓库目前本地没有任何 tag，远端 release 情况未能确认（gh 未登录，401）；若已有 `v*` 旧 release，新日期 tag 与之并存不影响 `previous_tag`（只要求 git 能解析到该 ref）。

## Gboard 布局：用上按键级圆角/背景（Xime abda05a 之后）

- 上游新能力（`/Users/kingzcheung/StudioProjects/Xime`，commit abda05ac「支持按键级外观自定义」）：
  `keyboard.<section>.keys.<id>` 可写 `corner_radius`(dp) / `background` / `background_dark`；
  只写外观字段时走 `mergeKeyBinding` 的 style-only 分支，保留原手势；文字色按背景亮度自动取
  #202124 / #E8EAED（KeyStyle.kt 的 contrastTextColor）。支持段：qwerty、qwerty_en、
  number、common_symbols（面板值键与功能键都吃），**T9 / 笔画 / 手写不吃**。
- 关键实测（用户 Gboard 底行放大图 654px 宽）：`?123` 和 `↵` 是**圆形键**；
  `?123` 淡薄荷 #B5CCBC、`↵` 亮薄荷 #8EF7BF（强化色）；逗号键面自带笑脸图标（不是滑动手势提示）；
  空格 = 5.9 个字母键宽、与字母键同色；地球键在 Gboard 中文键盘上不存在。
- 改法：`?123` 与 `enter` 写 `corner_radius: 40` —— Compose 的 RoundedCornerShape 会把半径夹到
  min(宽,高)/2，所以 40 = 「能多圆就多圆」，不依赖键高；宽度改 1.0 → 竖长圆键。
  底行 `?123 1.0 / ，1.0 / 🌐1.0 / 空格 5.0 / 。1.0 / ↵1.0`，合计 10。
- ~~字母键去掉数字角标的姿势：`swipe_up: { action: none, bubble: false }`~~ **已废弃（2026-11-07 晚）**：
  用户明确「上滑不能掉」「不必 100% 参考 gboard」，52 处全删，字母键只留 tap + long_press，
  上滑/下滑完全继承基座（q-p→1-0、a-l→～ ／ ： ； “ ” － （ ）、z-m→＊ ＠ 、 ？ ！ ％ ＃，下滑是五笔字根）。
  代价是键面重新出现角标，这是刻意取舍。
  只写 tap 不够 —— getSwipeUpLabel/getSwipeUpText 在「有 swipe_up 但 label/value 为空」时
  才不回退，若完全没有 swipe_up 会回退 `config.swipeUp`（getDefaultSwipeUp 的数字表）
  和 legacy `keys.swipe_up`。渲染用的是 rawSwipeUpLabel（已 null），bubble:false 兜住气泡。
- **没做强调色圆键**：按键级 background 是静态值，7 套主题各有各的强调色，写死会串色。
  要按主题上色得给 Xime 加令牌（如 `background: "@accent"`，在 KeyStyle 里解析成
  scheme 的 primary_color）。已在文件头「说明 4」写清原因。

### 回车改用主题色记号 accent（用户实现了 token 支持）

- 新能力（Xime 未提交改动里）：`keyboard.<section>.keys.<id>.background` 除 hex 外可写记号
  `accent` / `primary` / `special` / `key` / `keyboard`（可带 `theme.` 前缀，非法值视为未配置）。
  实现：`KeyColor.Token` → `KeyStyle.resolve()` → `LocalKeyStyleColors`（KeyboardLayoutScreen 统一解析）。
- 因此 gboard 的 `enter` 两段都改成 `background: accent`，删掉 `background_dark`
  （`KeyStyle.toKeyStyle` 里暗色 spec fallback 到 background，而 `accent` 解析时用的
  `LocalKeyStyleColors.accent` 已是 `getAccentColor(id, isDark)`，暗色自动是 accentDark）。
- accentDark 的来历：`KeyboardTheme.applyConfigOverrides` 里 `accentLight = primary_color`、
  `accentDark = lightenColor(primary_color, 0.45f)`（向白混 45%）。
  对 gboard（#4DB6AC）得到 #9DD7D1，接近实机截图的 #8EF7BF，但对不上（截图更亮更绿）。
- **发现渲染层缺陷**：`KeyStyle.kt` 的 `contrastTextColor` 用 `luminance() > 0.5` 二分选字色，
  对中间亮度色误判。实测 7 套主题 14 种组合里 7 个对比度 < 3:1，最差 1.76:1
  （red 暗 #F99890 给了浅字）。正确做法应比较两个候选字色各自的对比度取高者。
  已向用户报告并给出补丁，未擅自改源码（工作区有他未提交的 token 改动）。

### 追加：恢复字母键上滑（用户：上滑不能掉）

- 教训：为了「像 Gboard」把 52 个字母键的 swipe_up 写成 `action: none`，把功能一起砍了。
  Xime 的字母键上滑不是装饰：第一行 1-0、第二行 `～ ／ ： ； “ ” － （ ）`、第三行 `＊ ＠ 、 ？ ！ ％ ＃`，
  下滑还有五笔字根提示。这些都要保留。
- 现在的写法：字母键只写 `tap` + `long_press`（变音符），**不写 swipe_up**，
  让 `getSwipeUpLabel/getSwipeUpAction` 回退到基座的默认表。
  注意：写了 `tap` 就已构成键级整体替换，未写的 swipe_up/swipe_down 会走默认表回退，功能正常。
- 角标因此回到键面（q 上的 1、a 上的 ～），header 与 README 已改成「刻意保留」的说法。

### 修正 1：面板缝与 26 键不一致（纯配置，未动 Xime 代码）

- 现象：?123 面板与数字面板的键缝比 26 键窄，圆角却是对的。
- 成因：基座 `xime.yaml:509-516` 的 key 段给面板单独调过缝
  （`number: 2/2`、`symbol: 2/4`），而 `KeysConfigHelper.spacingFor()` 是
  「键盘覆盖优先于全局」。只写全局 3/5.75 → 26 键对、面板退回基座值。
  圆角没被带走，是因为基座那两条覆盖里没有 corner_radius。
- 修法：`gboard` 的 `key` 段显式加 `number: {3, 5.75}` / `symbol: {3, 5.75}`。
  面板段名 ≠ 键名：常用符号面板查 `"symbol"`，数字面板查 `"number"`
  （KeyboardLayoutScreen.kt:234-236）。
- 一般规律：凡是自定义 `key.spacing_x/y` 的布局，都要顺手把 number/symbol 覆盖掉，
  否则面板一定会「更挤」。fcitx5 早就这么写了，gboard 之前漏了。

### 修正 2：回车字号两端不一致（配置层的唯一解是文案长度）

- 成因：`KeyboardLayout.kt:931` 的 EnterCell 用 `ctrlFontSize`；主键盘该值为 null
  → `KeyButton.kt:950` 兜底 `text.length > 2 ? 14f : 18f`；而面板
  `PanelKeyboardLayout.kt:157` 写死 `ctrlFontSize = 14.sp`。所以「换行」(2 字) 主键盘 18sp、
  面板 14sp，差 1.29 倍。主键盘的「?123」是 4 字符 → 本来就 14sp，18sp 只有回车一个键。
- 配置层没有字号字段：`style.font_size` 是死字段（app/src/main 里没人读）。
- 用户选择：统一到 14sp。三处回车文案改成 `换行↵`（3 字符）→ 两边都落 14sp。
  代价：显式 label 会盖掉 Xime 随场景自动给的「发送 / 搜索 / 完成」。
- 遗留：`↵` 若在设备字体里缺字会显豆腐块，备选文案 `换行→` / `换行 `。

### 截图：gboard 布局实机四张

- 设备 RMX3551（1080×2412 / 480dpi），用 Xime 设置页自带的「点击此处开始输入测试」输入框取景，
  没有打开别的 App。
- 流程：`adb push` 最新 `xime.custom.yaml` → `run-as` 覆盖 `files/rime/xime.custom.yaml` →
  `am force-stop` 重启进程让配置生效 → `ime set com.kingzcheung.xime/.service.XimeInputMethodService`
  → 点测试框 → 截图 → `ime set ...sogouoem/.SogouIME` 还原默认输入法。

  2×2 的 HTML 表格图墙（width=240）。
- 几条实测结论：
  1. 中文 26 键的字母**永远是大写**：`getKeyDisplayLabel()` 在非 ASCII 态直接 `key.uppercase()`，
     与 shift 无关，配置改不了；英文键盘（isAsciiMode）才是小写。
  2. 数字面板回车文案是「确定」（`PanelKeyboardLayout` 的 `enterKeyText = s_queding`）。
  3. 空格键文字固定为方案名（这里是「五笔拼音」），配置层无法隐藏。
  4. 长按 ?123 直接进数字面板可用：`input swipe x y x y 800`。
- 坑：点击坐标要按 **1080×2412 原始截图**算，不能按缩略图算，否则会点到「主题与定制」进主题页。

## 新增 gboard/ 布局预设

- 仓库是 Xime（Android 输入法，Rime 内核）的键盘布局预设合集，每个目录一份 `xime.custom.yaml`，目录名即风格；已有 `wetype/`、`sougou/`。
- 本次新增 `gboard/xime.custom.yaml`：26 键 + 九键 + ？123 面板；亮色 #F1F3F4 底 / 纯白键 / #E8EAED 功能键，暗色 #202124 / #4A4D51 / #303134，强调色 Google 蓝 #1A73E8（暗 #8AB4F8）。
- 关键取舍：Gboard 无上滑数字 → 字母键不放数字角标；长按只出变音符号（无变音符的字母继承基座的小写/大写气泡）；中/英键用地球图标放在空格左侧（Gboard 工具栏那个「中」图标 Xime 做不出来）。
- 上游基座核对结论：地球图标两种写法都支持——`label: "@language"` 与 `icon: language`（KeysConfigHelper 里 icon 会去掉 `@` 前缀，与历史 `label: "@xxx"` 等价）。wetype/sougou 的 icon 写法没问题。
- `keys` 在 xime.custom.yaml 里是**同名键整体覆盖**（KeysConfigHelper.parseKeyboardGestureTexts：`defaultZh + customZh`），所以只写 `width` 会丢掉该键的手势；但 shift/delete/enter/space 在这些组件里有代码级兜底（Binding 为 null 时走内置），不会变哑键。
- 基座 `xime.yaml` 下载地址：https://raw.githubusercontent.com/ximeiorg/Xime/main/app/src/main/assets/xime.yaml
- 校验方式：`ruby -ryaml` 解析（本机 python 无 pyyaml），并校验每行 width 合计 = 10 列。
- README 表格已加 gboard 行。
- 未覆盖 `keyboard.number`：Gboard 没有独立数字键盘，会与「Gboard 布局」自相矛盾；配色仍会自动跟随主题。

## 按用户实机截图重做（同日修正）

用户反馈「主题色不对 / 圆角不像 Gboard」，并给了 654×529 的实机截图，重新测量后推翻了前两版的猜测值。

**实测几何（截图 654px 宽，键面 51×72，横缝 10，竖缝 19，圆角≈6）**
- 圆角/键高 = 6/72 ≈ 0.083 → 44dp 键高约 3.7dp，最终 `corner_radius: 4`（之前 10，确实太圆）
- 横缝/键宽 = 10/51 ≈ 0.196 → `spacing_x: 3.25`（缝 6.5dp）
- 竖缝/键高 = 19/72 ≈ 0.264 → `spacing_y: 5.75`（缝 11.5dp，Gboard 行距明显大于列距）
- Gboard 键是「窄高 + 大缝 + 小圆角 + 无投影」，`shadow.enabled: false`

**实测配色（暗色）**：底 #1B1D1B / 字母键 #2E312E / 功能键 #505350 / 字 #E8EAE7 / 强调薄荷 #8EF7BF（?123 是淡薄荷 #B5CCBC）。空格与字母键同色。
之前用的 #202124 / #4A4D51 / #303134 偏蓝偏亮，颜色不对的根因就在这。

**关键结论**：Gboard 键分三档色（字母 / 功能 / 强调键 ?123、换行），Xime 只有普通键+功能键两档，所以 ?123 与换行只能跟 Shift 同色 —— 除非 Xime 渲染层加第三档键色。这是目前与 Gboard 最大的剩余差距。

**主题库改为 6 套**：`gboard`（默认，亮暗跟随）、`gboard_black`、`gboard_blue`（蓝渐变）、`gboard_purple`（靛蓝→品红）、`gboard_mint`（绿→暖粉）、`gboard_lavender`（薰衣草→蜜桃）。理由：Gboard 的彩色皮肤实际是**渐变 + 半透明键面**，之前那 6 套深色实底皮肤是凭空想的。渐变端点色取自 Gboard 渐变主题截图。

**主题库最终形态（11 套）**
1. 强调色系列 6 套（跟随系统亮暗，结构不变、只换色相）：`gboard` 薄荷（默认）/ `gboard_blue` / `gboard_purple` / `gboard_green` / `gboard_orange` / `gboard_pink`。
   - 强调色经过两轮反馈定案：`0x1A73E8` 太艳（用户语）→ `0x6E96D8` 又太浅 → 最终 `0x2F6BC4`（hsl 216/61%/48%，白键对比 5.2:1）。
   - 选色判据改为「白键对比度」而不是主观明暗：<4.5:1 就会显得发灰发浅（`0x6E96D8` 只有 3.0:1）。后续任何强调色都按此校准。
   - 每套都是「中性键面 + 同色系浅染」：底色/字母键/功能键都随色相微调（如蓝：`#EDF1F7`/`#FFFFFF`/`#C9D6E8`，暗 `#1A1C20`/`#2D3036`/`#4F535A`）。
   - 选中候选文字分两档：亮色用强调色 ×0.72（保证对比度），暗色用强调色原色。
2. 固定色：`gboard_black`、`gboard_gradient_blue/purple/mint/lavender`（渐变为 Gboard 真实皮肤：渐变底 + 半透明白键面）。
- 生成方式：`/tmp/gen_gboard_schemes.rb` 按明度关系批量生成 6 套强调色，再拼手写的黑色/渐变段，Ruby 按 `^color_schemes:` 与 `^keyboard:` 切分替换。

**验证脚本要点**：`magick img -fuzz 6% -fill white -opaque '#颜色' -fill black +opaque white -define connected-components:verbose=true -connected-components 4 null:` 可量键框；再对键角做 txt 逐行内缩统计得圆角。注意 ImageMagick 的 `-threshold %` 走线性灰度，直接阈值法测不准。

**逗号手势**：Gboard 逗号键上滑是表情入口（截图里逗号上方有个笑脸）。Xime 里用 `swipe_up: { label: "表情", action: switch_route, value: emoji, display: key, bubble: false }` 复刻，中文/英文两段都改了。CommaCell 的手势提示只接受字符串，接不了矢量图标，所以 label 用 emoji 字符 `😊`（用户要求键面是表情）。坑：英文态 `k2SwipeUpLabel` 取的是 value（"emoji"），会把路由名印在键上，故英文段改成 `display: bubble` + `bubble: false` 只绑动作不显示提示；要修需改 CommaCell 的 isAsciiMode 分支为 label 优先。原来逗号上滑的「。」由句号键 tap 承担，没有丢功能。

## ?123 与符号面板圆角（用户报的两个 bug）

- `tap` 必须写 `mode_change_common_symbol`，不能写 `mode_change`：后者跳「上次用过的面板」，并由 `SettingsPreferences.modeChangeTargetIsNumber` 持久化 → 长按选过数字后，之后每次点 ?123 都进数字面板，观感即「功能反了」。
- 长按两项顺序按气泡图标排：ModeChangeCell 的 `longPressDrawableIds` 固定为 `[t9, t26]`（九宫格 / 全键盘），所以第一项放「数字」、第二项放「常用符号」。
- **坑**：Key 段键名 ≠ 面板段名。常用符号面板段名是 `common_symbols`，但 `KeyboardView.kt:1206` 取圆角时传的是 `"symbol"`（`keyCornerRadiusFor(kbKey, "symbol", …)`），所以之前写的 `key.symbol.corner_radius: 8` 正好把 ？123 面板撑成 8dp。已删除 `symbol` / `number` 覆盖，让它们继承 `key` 的 4 / 3.25 / 5.75；只有 t9（3 列大键）单独 10。
- 顺带把 shift/delete 的 1.45 改成 1.5，Z 行宽度从 9.9 补到 10.0。

## Gboard 主题色最终来源：APK 里的 protobuf 配色表（不再靠截图猜）

- APK 路径：`~/Downloads/com.google.android.inputmethod.latin_18.5.9...apkm`，里面 `base.apk` → `assets/theme/style_sheet_*.binarypb`，每个主题一份（color_black/blue/blue_grey/brown/cyan/deep_purple/green/light_pink/pink/red/sand/teal + default、default_light）。
- 结构：顶层 field 2 = 重复项，每项 `2.1` = 属性名字符串，`2.2.1` = varint 颜色（0xAARRGGBB）。用通用 protobuf 游标解析即可，无需 .proto。
- 关键属性名 → Xime 字段：
  `default_keyboard_background_primary_color` → keyboard_bg_color；
  `default_bordered_key_color` → key_bg_color；
  `default_bordered_key_dark_color` → special_key_bg_color；
  `default_generic_accent_color` → primary_color；
  `default_label_color` → key_text_color。
- adb 校验路径：`am start -n .../launcher.LauncherActivity` → 点「主题」(275,1211) → 颜色项会弹预览页（取消/应用）→ 点「应用」→ 打开带输入框的应用截屏取色。注意单点缩略图只是打开预览，必须再点「应用」。
- 最终 **7 套**：`gboard`（浅/深合并，跟随系统）、`gboard_google`（Google 浅/深合并）、`gboard_blue/red/green/teal/cyan`（固定色）。旧的 11 套（薄荷、紫、橙、粉、纯黑、4 套渐变、浅染）是按主观推算出来的，已删除。
- 用户明确要求「浅色和深色应该合成一个主题」：Gboard 因为主题固定才拆两格，Xime 的 scheme 自带 `_dark` 字段会跟随系统。合并写法：keyboard_background.color/color_dark、keyboard_bg_color(_dark)、key_bg_color(_dark)、special_key_bg_color(_dark)、key_text_color(_dark)、candidate_*_dark。**`primary_color` 没有 _dark 变体**，强调色只能取亮色那支，暗色靠 candidate_selected_*_dark 补。
- 已知取舍：绿色主题白字/键面只有 2.61:1（Gboard 自己的值就这么低，保持原样）；浅色与 Google 浅色只差强调色，而 Xime 的强调色只作用于候选栏图标，所以这两套在 Xime 里几乎一样。
- 设备上的 Gboard 已还原成「默认」主题。

## fcitx5-android 布局与主题（新增 fcitx5/）

- 数据来源：用户提供 APK `~/Downloads/org.fcitx.fcitx5.android_114.apk` = **0.1.3 / versionCode 114**；与上游 tag `0.1.3`（commit 048f581c）源码一致。配色写在 `data/theme/ThemePreset.kt` 的 `Theme.Builtin` 常量里，**不在 res/values**，aapt 导不出来，只能读源码。
- 26 键键位（TextKeyboard.Layout）：Q行 alt 1-0；A行 alt `@ * + - = / # ( )`；Z行 alt `' : " ? ! ~ \`；底行 `?123 1.5 / ，1.0 / 🌐1.0 / 空格4.0 / 。1.0 / ↵1.5`（fcitx5 用 percentWidth 0.1/0.15，空格权重 0 吃剩余）。
- 数字键盘（NumberKeyboard.Layout）：`+ 1 2 3 /` · `- 4 5 6 空格` · `* 7 8 9 退格` · `ABC , !?# 0 = . 回车`，宽度换算成 10 列：符号 1.5、数字 2.333、底行 1.5/1/1.333/2.333/1.333/1/1.5。
- 几何（ThemePrefs.kt）：keyRadius=4、keyHorizontalMargin=3（缝 6）、keyVerticalMargin=7（缝 14）、keyBorder 默认关 → 无阴影。**注意**：Xime 的 `keyboard.key` 是字段级合并，基座里 number(2/2)、symbol(2/4) 的覆盖会留着，必须显式写回 3/7。
- 主题映射：keyboardColor→keyboard_background、barColor→candidate_bar_background（**该字段是合法 schema**，支持 color_dark）、keyBackground→key_bg_color、altKeyBackground→special_key_bg_color、keyText→key_text_color、genericActiveBg/Fg→candidate_selected_*、accentKeyBackground→primary_color。11 套合并成 6 套（pixel/material/nord 各合亮暗；deep_blue/amoled/monokai 固定色）；Transparent 两套放弃（0x00000000 会被 longToColor 补成不透明黑）。
- 正式版 fcitx5 默认主题是 Pixel（ThemePrefs 里 DEBUG 才用 Material），所以 `style.color_scheme` 指 fcitx5_pixel。
- 无法复刻：回车是**圆形强调色**按钮（KeyView.onSizeChanged 的 insetOvalDrawable，直径 min(w,h,35dp)）；空格是 spaceBarColor 内缩矮条；alt 符号画在键面下方而 Xime 画在键角；?123 在 fcitx5 是切数字键盘、符号走 !?# 的 PickerWindow。
- 顺带发现 gboard 那份额度的真 bug：自定义键只写 `tap` 时，`getSwipeUpLabel/Action` 会回退代码里的默认数字表（q→1…p→0），所以「字母键不带数字角标」其实没生效；要显式写 `swipe_up` 才能清掉。
